日期：2026-10-29。本轮只调查，未修改提取代码、规则、提示词、接口或历史评分，未访问 NOC，未请求模型。

- `source-hashes.json`：所读审计、回放、分析和包材料哈希，原材料逐项与清单校验。

复现命令（不调用模型）：


读取原包并验证清单和材料哈希；从审计实际请求重建证据对象，去掉仅供请求显示的 `recorded_at` 附加项，核对请求证据摘要；重新执行原始 JSON 的建议分离、结构补全、时间归一和 grounding。三十一单的 normalized、before_grounding、after_grounding 均逐项一致；三十单通过、F23 仍因 `EVIDENCE_QUOTE_MISMATCH` 拒绝。

成功单在完整保存证据上再次执行最终引用校验，完整 Extraction（含 quote_checks）与三十份 `replay.json` 一致。请求证据有可用文本裁剪，字符范围相对于请求文本；最终报告范围相对于完整证据，不能直接拿这两种范围比较。本轮未重新运行附件 OCR 或完整解析器，不声称重新验证了附件识别质量；语义调查以已保存证据与原包为依据。

## 三、规则实际在哪一步清空

源文件为 `src/noc7/providers/text_ground.py` 和 `src/noc7/extract/baseline.py`，流水线顺序见 `src/noc7/providers/text_http.py:_decode_payload`。

1. **结构补全。** `_repair_quote_element` 调用 `_finish_conclusion`，要求 value 与某候选 statement 完全相等；仅语义一致或一方多标题也不能保留值。F06 因此先变未知。
2. **时间用途重判。** `_ground_time` 逐候选调用 `_time_of`。字段仅认 `_FIELD_TIME`，不读字段中文 label；文本主要依赖 `_time_kind` 的有限短语及同分句上下文。所有本轮被清空的选中时间都变成 `observation`。起障仅允许字段起障、客户报障起点或告警；恢复仅允许恢复字段或客户确认恢复。类别不在白名单时 `_clear` 清空值、selected、结论引用，保留候选。
3. **原因类别重判。** `_ground_cause` 用 `_cause_of` 对摘录重新调用 `cause_kind`；返回空就删候选。根因入口只覆盖少量中英文断缆词；`cause` 字段兜底为 `investigation_finding`，这种类别不允许作为正式原因。confirmed 还要求 `root_cause_confirmed`，不自动降为 documented。
4. **引用校验。** 清空发生在最终校验之前。本批成功目标不是因引文不存在而被删；F23 是后续独立引用拒绝。即使保留其原因，整单也不能据此直接交付。

二十一个答案中至少十三个有明确本地限制，其中包括两个告警时刻，不代表十三个都可当实际业务起止／正式根因。样本定向选择且可共享故障，比例只解释这批删除，不能推广为系统准确率。保留原始模型也会保留错误、推测及来源冲突；只扩充词表也会遗漏归一时区和状态等级问题。
