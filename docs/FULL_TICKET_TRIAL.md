# 完整工单（含已导出结案材料）真实试跑

日期：2026-10-29。完整输入场景共 **31 张去重工单**；生成 **30 套审核报告及公司格式 Word（96.8%）**，**1 张因引文不匹配被拒绝（3.2%）**。报告是待审核草稿。现象、处理过程覆盖较高，但正式起障／恢复时间和原因仍大量留空，不能把“生成了 Word”当作“报告已经填完整”。

输入使用未切分原包，保留已经导出的最终字段、结案处理记录、邮件、RFO 与附件。未调用旧评估的首次结案截断逻辑。这里的完整是“对现有包不再截断”，不保证源系统全部历史附件均已导出或被成功解析。签名、衍生摘要、低质量片段及失败／未支持材料仍按现有规则隔离，截图仅做本地解析，原图不发外部模型。实际发送证据逐单留存在模型审计中。

三十份成功结果中，排除六十份导出器源留档 JSON 后，业务材料共五百四十二份：`parsed` 四百八十七份、`needs_review` 五十五份，`failed`／`unsupported` 为零。此计数只覆盖交付成功集合；`needs_review` 表示仍有覆盖或质量限制，未将其写成全部材料解析完整。

## AI 建议，待确认

三十份成功审核报告中，责任方候选覆盖 **11/31 张（35.5%）**，共 **16 条**；地点候选覆盖 **30/31 张（96.8%）**，共 **108 条**。这 **124 条候选**均能严格定位到引用原文。原始建议 `value` 非空分别为责任方 **0 张**、地点 **3 张**，与候选覆盖是不同指标，不能相加。

地点候选可以是端点、测试节点、告警点或尚未定位的区段；它们的原文存在不证明是实际故障地点。责任候选原文也不等于正式定责。这些建议只在审核 Markdown／HTML 展示，公司 Word／HTML 不使用建议补填正式结论。

将被拒工单的已绑定原响应也纳入后，三十一张原响应均可解析：责任方仍为 **11 张／16 条候选**；地点为 **31 张／111 条候选**，原始非空值四张。两栏共 **127 条候选均严格匹配原文**。被拒单额外有三条地点候选，但整单因其他正式引用不匹配仍不交付报告；建议有据不能抵消正式校验失败。

这说明正式填出不足并非都发生在模型读取阶段。本地处理会重判时间用途、原因类别及确认等级，再决定保留候选和正式值；本轮没有逐条审定被清空结论是否正确，不能反过来把重算前的值当作已验证正确答案。

## 独立准确率与结案一致性

本轮不报告独立准确率，也不拿输入中的同一份人工结论作为独立答案重打分。结案复述一致性未新增逐条语义标注，因此本轮没有该项数字；引用存在不能替代语义一致性。已结单状态同样不是人工审核证明。旧评估仍保留原来的参考资格、支持审定和防泄漏成绩。

本轮能回答的是：系统交付了多少套草稿、各栏填了多少、保留了多少可定位的审核线索。是否认错责任主体、把端点当故障点、归一错时间或删掉了正确原因，仍需业务核对。

## 运行与复核方法

使用 `config/models/deepseek.json` 的 DeepSeek `deepseek-flash`，当前提示词和本地规则不变，三个工作线程；真实文本外发通过既有授权闸门。初次三十一单运行中，两张在发送前超过配置的 524,288 字节本地上限；仅对这两张将本地上限提高到 4,194,304 字节后运行，材料没有截断，两张均成功。保留初次失败记录、容量配置及新审计；这不是对已获得答案重新生成。另一张因 `EVIDENCE_QUOTE_MISMATCH` 拒绝，未绕过或再次请求。

运行命令（输出必须为新的仓库外目录）：

```sh
uv run python scripts/run_full_ticket_trial.py \
  ~/.noc7/real ~/.noc7/sample-expansion-it6b5svf/captures \
  --out ~/.noc7/full-ticket-trial-20261029 \
  --model-config config/models/deepseek.json --workers 3
```

历史运行目录已经存在，不要原样重跑此命令。容量补跑及最终汇总复核脚本也保存在该私有目录中；完整原响应与 `replay.json` 可用于无网络复核。报告均由同一份最终 `AnalysisResult` 生成，没有为 Word 再次抽取。

三十份结果无网络回放后，七要素、建议、证据、事件、问题及引用核验逐项一致；三十份 Word 的 ZIP 完整性与主文档结构检查全部通过。输入包清单及材料哈希复核不变。

基线全量测试 **506 项通过**，新增统计器合成测试 **3 项通过**；Schema 与 gold 契约检查通过。额外执行默认全链路合成对照：十五包均可运行，其中两包仍存在与 gold 的语义差异，返回码为 1；它与 pytest 是不同检查，本轮未修改抽取链路，也不将该项写成通过。

本机私有目录：`~/.noc7/full-ticket-trial-20261029/`。`index.html` 提供三十份审核报告、公司 HTML／Word 的逐单入口；`mapping.json` 是源身份映射；`metrics.json`、`summary.json`、`subgroups.json`、`raw-summary.json`、`paired.json` 保存统计；每单 `audit/`（容量补跑为 `audit-capacity/`）保存实际请求证据、原响应及重算快照；`verification.json` 保存回放和 Word 检查结果；拒绝记录在对应单的 `failure.json`。真实单张报告不在项目文件页。
