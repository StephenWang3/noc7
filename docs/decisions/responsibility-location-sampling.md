# 责任方与故障地点的定向扩样

## 决定与范围

用户选择人工结论优先、最多新增二十张：先核对已保存报告和明确人工结案说明，再核对邮件及供应商 RFO；不以有附件、运营商编码或 `fault_area` 非空代替人工答案。相比 RFO 优先，此方法覆盖更多结论来源；相比分类字段引导，不依赖尚未核实的业务标签，但需要逐单审查。

查询限于最近三个月创建且当前已结案的业务工单，按创建时间从近到远检查最多二百条去重候选。已有评估工单排除，优先补足责任方、地点各十张有独立输入支持的工单；同一张可覆盖两栏。达到二十张或候选上限即停止，不足按实际数量报告，不扩展窗口补齐数字。

执行前在新抓取的 `main` 独立副本运行全量测试。测试失败时停止采集和模型请求，不把合并前测试当作合并后证据。

## 证据与冻结

复用只读采集器的请求白名单、串行限速、有限计划和遇错停止机制。人工结论转录登记作者、时间、审核状态和原文锚点；自动保存记录不证明人工审核，缺失审核人不能标成已审核。字段编码仅保留来源及可核实标签，不能据其定责。

沿用 `human-reference-evaluation.md` 和 `preclosure-email-and-fact-recall.md`：首次明确结案动作作为截止，参考、副本、摘要及缺少历史证明的最终字段均隔离。截止前独立邮件须先核对源邮件身份、发送方、时间、正文及唯一挂接，再逐事实登记审定引文；不豁免整封邮件。缺少支持、来源冲突或无法核对时间的事实分别列出，不成为提取效果分母。

人工归因的记载与正式认定分层；故障段与端点、告警位置分开。冻结事实、同义词、支持及允许状态之后才运行两侧提取，不根据输出调整标注。修订需要新建冻结集，旧集和旧评分保留。

原文提及施工单位、维修方或客户机房，不等于明确归因；仅有推测及角色归属不转成责任参考。原始事件时段与首次结案时间矛盾时不猜日期或时区。人工短参考的同文副本若无法可靠隔离，也不凭自动长指纹检查通过获得资格。旧完整包可在身份、参考记录、正文、截止点和所有材料哈希核验一致后复用，不能仅凭标题匹配。

## 对照与交付

规则与 DeepSeek 只读取同一个新冻结集的 `inputs`，使用现有解析器、证据校验和评分器。模型调用沿用已批准的真实文本链路，不发送原图；保存原始响应、本地重算诊断和回放。失败、拒绝及待判定均报告，不通过删去失败工单美化结果。

评分单位仍为来源事实；覆盖工单数单列，不将邮件转录、重复来源或同一事件的多张工单称为独立故障数。逐要素报告一致、遗漏、冲突、待判定、未确认输入支持、来源冲突及实际分母，零分母不计算一致率。定向便利样本用于探索性参考对照，不代表总体准确率或业务正确率。

真实数据、身份映射、筛查台账、支持审查及长篇明细仅存于 `~/.noc7/` 新私有目录；仓库仅提交白名单计数、操作说明与结论。不修改生产抽取规则、共享 schema、外发闸门或旧评估集。
