# 0004 合成工单与标准答案：按调研问题模式编写，用锚点和要点判分

- 日期：2026-10-27
- 阶段：A0
- 状态：已采纳
- 相关：`fixtures/bundles/`、`evals/gold/`、`src/noc7/schema/gold.py`、`src/noc7/goldcheck.py`、ARCHITECTURE_OPTIONS §7.2–7.3

## 背景

评测要用合成集和真实集。合成集可以进仓库、可以发给外部模型，但不能含任何真实工单内容、编号、客户信息或附件。调研时没有保存工单原件，只有脱敏摘要里的 11 种问题模式（S01–S10、X01）。

标准答案要能自动判分，但又不能和 A1/A2 的实现细节绑定：解析器怎么切片段、片段编号是什么，在写标准答案时还不知道。

## 可选方案

| 方案 | 做法 | 缺点 |
| --- | --- | --- |
| 1 标准答案写成完整的 AnalysisResult | 期望输出逐字段比对 | 绑定证据编号；文本必须逐字一致，不现实 |
| 2 只标每个要素的值 | 一个期望值 | 无法表达“允许为空”“必须保留某个候选”“必须报某个问题” |
| 3 标准答案描述“正确结果应满足什么” | 允许的状态、期望时间（带容差）、文本要点（同义写法任一命中）、必须保留的候选、不得出现的值、证据锚点、应报的问题、标注理由 | 判分逻辑稍复杂 |

## 选择及理由

选 3。

1. **15 个合成工单包**：S01–S10、X01 各一张，保留调研发现的问题模式，内容全部改写；另加 4 张 PRD §7 必测用例：P01 时间倒置/负历时、P02 UTC 与 GMT+8 跨日 + 无时区海外设备日志、P03 附件夹带指令 + 同电路作废单、P04 正向对照（七要素都有直接依据，检验系统不会过度保守）。
2. **附件真实可解析**：S10 的 QoS 曲线 PNG、X01 的交付确认长图、P03 的 DOCX、P04 的 PDF 由 `scripts/make_fixture_assets.py` 生成，A2 能用它们做真解析。S10 的分类别丢包统计**只在截图里**，用于“有附件 / 无附件”对照实验。
3. **证据锚点**：材料编号 + 字段键 / 处理过程序号 / 邮件消息序号 / PDF 页码，与解析器的编号无关。`noc7 gold check` 会核对每个锚点在工单包里真实存在且非空。
4. **文本按要点判分**：每个要点给几种同义写法，命中任一即可；时间按分钟比较，带容差，并检查时区来源。
5. **允许多种状态**：例如 documented 或 confirmed 都算对；只允许 unknown/conflicted 的要素不能给期望值（防止标准答案自相矛盾）。
6. **每个要素写标注理由**（至少 8 个字），这些理由就是答辩时解释“为什么系统应该留空”的素材。
7. 合成数据安全检查写成测试：IP 只能用文档保留网段（192.0.2.0/24、198.51.100.0/24、203.0.113.0/24），域名只能是 example 域，编号以 `SYN-` 开头。

## 后果与代价

- 标准答案由编写合成工单的人（本阶段由 agent）标注，**需要懂业务的人复核**，尤其是责任和原因的判断口径；
- 合成样本覆盖的是已知的问题模式，评测结果必须和真实集结果一起报，不能只用合成集说明效果；
- 生成附件需要 matplotlib（只在 `fixtures` 依赖组里）。附件已提交，平时不需要重新生成；重新生成后要 `noc7 bundle rehash` 更新哈希。
