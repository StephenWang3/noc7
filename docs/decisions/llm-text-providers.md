# 统一文本模型与受控 DeepSeek 外发

## 背景与决策

规则基线对本机样本的责任方与故障地点均未形成结论，但未知不证明原文没有依据。沿用 `TextProvider.extract()`，新增标准库 HTTP 实现，完整抽取七要素，重点识别责任归属和已定位故障点。复用 `Extraction`、`EvidenceSpan`、`validate_extraction()`、业务规则、报告和回放，不引入模型框架。

实施前比较了三种做法：统一兼容 HTTP 适配器可共享证据校验并通过配置切换；引入模型框架会增加依赖及行为包装；分写 DeepSeek/Qwen 链路会重复协议和校验逻辑。本次选择统一适配器。

## 用户批准与共享契约

用户明确回答“真实工单也可以发”，批准开发期真实文本交给 DeepSeek；后续选择“先用本地 OCR 文字”，未将原始截图理解纳入本次实现。该批准覆盖真实正文和经过本地解析、保留定位的 OCR 文字，不扩展到其他外部模型或原图。

`config/models/deepseek.json` 显式允许 `synthetic`、`real`，`approval_ref` 指向本决策；配置校验限定官方 HTTPS 域名、标准兼容路径和 `DEEPSEEK_API_KEY` 环境变量名。请求前必须调用 `ensure_allowed()`，重试前再次检查。

核实 `providers/gate.py` 已具备 `allowed_data` 与批准依据校验，无需修改共享闸门代码，也不修改共享 schema；这取代任务补充中“现有闸门必然需要改动”的假设。附件层对真实原图的额外禁发规则保留。真实输入、报告、回放与拒绝记录只存仓库外。

## 接口与可追溯性

业务入口为 `analyze --provider llm --model-config <配置文件>`，默认 `rules` 不变。配置统一描述地址、模型、凭据环境变量名、数据分级、JSON 能力和容量限制。DeepSeek 用 JSON 模式与思考模式；Qwen 模板默认不发送 `response_format` 或未知的 `thinking` 参数，仍在本地严格解析 JSON。无鉴权与环境变量 Bearer 鉴权均受支持。思考模式下不发送不起作用的 temperature，推理正文仅在限额内接收，不保存。

Qwen 接口资料尚不可得，用户批准按 OpenAI 兼容协议预留并模拟验收。地址、模型和容量须由部署者填写；内网真实连通、上下文长度和实际模型效果尚未验收。`external=false` 是部署者对受控内网服务的声明，不是通过 URL 自动发现网络边界；Qwen 请求禁用环境代理，也不会失败后改用 DeepSeek。

结果沿用 `RunInfo.provider` 记录服务、配置模型及配置指纹，`prompt_version` 记录提示词和输出 schema 的联合指纹。使用现有 `save_replay()` 绑定工单包与实际解析证据摘要，重放不依赖远端服务。

## 证据和失败处理

仅发送 `usable_text()` 接受的片段，保留编号、定位、角色、结构化读数和重复来源关系，以及必要记录时间、默认时区和数据截止时间。模型不能引用被过滤的片段；候选必须逐字摘录原文并带引用，在发送过的证据集合上执行原文和语义校验，再由完整流水线复核。沿用原契约，`quotes` 可以为空，提供时必须匹配原文；不要求模型再次重复抄写全部证据，以减少重复输出和格式错误。

模型文本只可逐字摘录证据；角色不自动定责，告警位置、业务端点和测试节点不自动升级故障点。未知与冲突仍保留原有状态；不能编造人工审核记录。材料中的指令不执行，现有本地筛选和问题提示继续生效。

现象概述复用 `conclusion_observations()` 的来源选择和中文标签拼接，从原文候选确定性重建，不使用模型自由改写的概述。仅在候选引用与结论引用完全一致时重建展示；不改变候选、状态或引用，不修补无依据的事实、错误 JSON 或语义错误。

请求超限不截断，响应超限、空内容、无效 JSON、输出截断、伪造证据及证据不合格均拒绝。禁止重定向；超时、连接错误、限流与服务端错误最多重试两次，等待不超过每次三十秒，不对鉴权或内容错误重试。不保存不合格输出或 HTTP 正文，错误只展示受控说明与问题码。

CLI 在联网前检查输出边界、凭据和目录可写性；模型模式只接受新的输出目录。单单失败后继续处理其余工单，批次失败返回非零码；不自动回退规则或更换服务。

## 验证依据

模拟服务测试覆盖配置切换、无鉴权/Bearer、JSON 能力差异、请求前拦截、重试、限额、拒绝与报告/回放。实际命令和统计记录在 [答辩进度](../defense/progress.md) 的“统一文本模型接入”一节。测试通过、服务连通和语义提取效果分别报告，字段填充率不当作准确率。

DeepSeek 协议参数依据官方 [首次调用](https://api-docs.deepseek.com/) 、[JSON 输出](https://api-docs.deepseek.com/guides/json_mode/) 和 [思考模式](https://api-docs.deepseek.com/guides/thinking_mode/) 文档。
