# 责任方与故障地点：实现、受限试跑和离线复核

## 当前结论

已实现业务关系、来源优先级、三类责任、城市级定位及公司 HTML／Word 正式栏接入，自动最高 `documented`，并显示“有记录，未经人工审核”。新责任规则要求明确归属路径提供专门责任依据，不能只用供应商身份、反馈标题或客户侧现象。

**完整的新提示词在线验收尚未完成。** 固定 22 张已结单均已尝试修改前后试跑；提供方先返回 HTTP 503，随后返回 HTTP 402。只读余额接口确认账户 `is_available=false`，因此停止在线请求。责任证据门槛收紧后的当前提示词没有真实模型回答，不能把此前回答的回放称为新提示词效果。

当前代码对已取得回答完成禁网回放：交付 **14/22**，正式责任方和地点均为 **0/22**。责任和地点原始建议候选分别覆盖 **11/22、14/22**。这些数字不证明材料没有责任或地点：存在缺少新关系锚点、来源类别未明、城市不明确及非故障点候选等程序阻断；六张根本没有模型回答。代码和合成验收已经完成，当前新提示词的完整真实重跑仍受账户余额阻断。

## 逐项复核与门槛修正

对诊断阶段的五条正式责任及另一条被结构约束挡住的客户责任候选逐条阅读原文，保留原始模型状态、选中项、关系、程序选择和引用。发现：

- 三条明确语义误用：把一般供应商角色／反馈套成责任，把客户侧漏洞及本方端口不限制的排查范围套成客户责任，以及在仍联络供应商上门时把客户侧设备故障直接套成客户责任。
- 一条角色归因仍待业务复核：选中断言和来源只有供应商名称，另有链路故障上下文，但角色到责任的连接不充分。
- 两条可支持有记录的供应商故障归因：原文分别说明合作方光缆被割断、供应商网络内断纤并由其现场队伍修复。它们不是人工定责；其中一条明确 RFO 被模型降成供应商反馈，另发现两条一般报障／催查被模型写成上门锚点。

这说明关系字段合法、引文存在仍不证明语义正确，不能把诊断阶段五条填出作为五条正确答案。程序补充通用结构约束：客户侧设备仍有其他提供方上门线索时不得直接采用客户责任；明确归属必须另给 `responsibility_quote`，包含在关系上下文中，来源引文不能代替责任证据。没有添加真实工单专属词表，也没有按人工复核结果改写原响应或替模型补锚点。

已保存的这些回答都没有新专门责任锚点，因此当前正式责任回到零；这属于兼容保护，不证明模型已学会新要求。新的结构和提示词已通过合成 HTTP、解码、规则、导出再加载验收，**仍须账户恢复后取得当前提示词的新回答，重新完成相同 22 张真实验收**。地点没有新增正式值，不宣称城市定位召回改善；城市语义和材料支持程度也没有独立全量标注。

## 评审修正后的核验

评审指出此前专门责任引文仍可重复自查句或运营商角色句，不能单靠匹配通过正式门槛。本次收紧明确归属：必须 `basis=formal_determination`、`customer_device_fault is False`，且自查、供应商上门、联通上门锚点均为空；`claimed` 只留候选。客户设备故障为真或未知不能从明确归属短路，须满足完整上下文条件。客户责任遇到同候选或同事件同范围其他候选的可靠上门锚点即被阻止，不再依赖设备故障标志为真。提示词正式认定示例及正例测试使用明确责任认定原文，不再把单独“请客户自查”作为正式责任正例。

供应商和联通上门锚点同时存在时，两条路径均待核对。同层同事件同范围、引文可靠且否定同一责任类别或城市的候选，即使 `contradicts=[]` 也形成冲突；不同事件、范围、层级或不可靠引文不混作同层反证。城市正式采用一律要求 `single_city`，不再因 `granularity=city` 放过未知范围的跨城端点。角色／端点字段在 `pending_reason()` 中提前留为 unknown，九种字段的回归均验证起障和原因仍保留，未触发整单拒绝；不存在的来源及其他正式要素的硬校验不变。

新增三十一例回归，全量 **716 项通过**，JSON Schema 一致性及差异空白检查通过。未新增在线模型请求，对原固定二十二张再次禁网回放，输入包、证据和原回答绑定全部与前次一致：仍十四张成功、六张无回答、一张格式不合格、一张实质引文拒绝；正式责任和地点均零，十四份回放相等、结果再加载及 Word 包读取均通过。逐单差异保存于 `~/.noc7/responsibility-location-business/review-comparison.json`，本次报告位于同目录 `review-verified/`；不覆盖前次记录。默认完整链路的两包既有 gold 差异未变化。

这次验证证明结构门槛及反例拦截，不证明新提示词已在线取得正确责任与城市判断；最新提示词的完整真实在线验收仍未完成。
