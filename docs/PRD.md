# NOC 故障七要素提取与报告生成 PRD

版本：v0.1｜日期：2026-10-27｜状态：开发基线草案

## 1. 产品目标

面向 NOC 值班人员和报告审核人员，把工单字段、处理日志、邮件、截图和文档整理成有原文依据的故障七要素，输出结构化 JSON 和标准 Markdown/HTML 报告，减少人工查找、整理、翻译和重复录入。

产品交付的是可审核的阶段报告或结案草稿。材料缺失时明确留空并列出待补项；不为满足完整率编造时间、根因、责任或修复动作。

## 2. 调研依据和限制

## 3. 用户与场景

- 值班人员：导入材料，查看自动时间线和七要素，补充材料，快速形成阶段报告。
- 故障负责人：核对恢复、根因、责任和实际故障点，处理冲突，生成结案草稿。
- 审核人员：逐项查看原文依据，修订并批准报告版本。
- 管理人员：在获得相应数据权限后查看处理耗时、人工修改率和质量评测结果。

## 4. 范围和优先级

### P0：首个可试用版本

1. 本地或内网部署；工单结构化JSON导入、文本粘贴和材料上传。
2. 中文/英文文本、邮件正文、PNG/JPEG截图、PDF、DOCX、EML解析；不支持的格式明确提示，不能静默漏掉。
3. 工单材料清单、解析状态、失败重试及源文件预览。
4. 事件时间线、七要素提取、证据引用、缺失及冲突检测。
5. 人工逐项修订和复核，保留机器结果与人工结果及修订记录。
6. 阶段报告、结案草稿两类模板；JSON、Markdown、HTML导出。
7. 固定评测集、质量指标和按单耗时记录。

### P1：真实数据试点

1. NOC只读连接器，增量同步字段、日志、邮件和附件；取决于可用接口或授权导出方案。
2. 新材料触发重新分析，展示相对已审核版本的变化，不覆盖人工结论。
3. 工单关联候选、资源编号别名和有效期核对，人工确认后合并事件视图。
4. 正式单点登录/角色权限与源系统权限映射；多用户审计和运营指标。
5. 经业务确认的报告模板及可选中英双语报告。

### 暂不纳入

自动派单、自动报障或追单、自动认责、自动关单、对外发送报告、修改生产NOC数据、全网根因诊断、模型训练平台。未来增加上述动作须另行定义产品范围及授权流程。

## 5. 用户流程及界面

### 5.1 材料导入

创建分析任务 → 填入工单编号/导入工单包 → 上传材料 → 显示材料清单 → 解析 → 分析。

同一文件按内容哈希去重。重复邮件引用按内容识别，原文仍保留。用户可追加材料；解析失败的文件不阻塞其他文件，但任务显示“材料不完整”。首版建议限制每文件25MB、每任务100MB、每个PDF100页，阈值可配置；超过限额明确拒绝并提示拆分。

### 5.2 审核工作台

左侧：材料与原文预览；中间：七要素和时间线；右侧：缺失、冲突及待核实清单。

点击任何提取值可定位原文页码、段落、邮件或日志条目；图像证据支持区域定位。使用“有直接证据／待确认／有冲突／未提供”等明确状态，不能只显示一个百分比。用户可接受、改写、清空结论，指定证据或填写修订理由。

时间线优先显示实际检查、操作和结果，可展开查看签收、转派等流程事件。客户报告与网管观测分列，不将检查范围不同的正常结果自动判成客户误报。

### 5.3 报告预览与导出

阶段报告包含已知事实、处理经过、当前状态、未确认事项及下一步待核实内容。结案草稿增加恢复依据、根因和责任结论；未知项可以保留，但必须显式披露。

生成草稿始终允许；未解决的关键冲突或未完成必要审核时，不允许标记为“已审核结案报告”。内部版本可显示完整证据索引，对外版本仅提供脱敏预览和下载，不自动发送。

## 6. 七要素业务定义

| 字段 | 提取内容 | 必须区分 |
| --- | --- | --- |
| 发生时间 | 实际起障时间或明确标注的候选时间 | 首次观测、报障、建单、设备告警时间 |
| 结束时间 | 业务恢复时间及依据 | 告警清除、客户确认、关单时间 |
| 故障现象 | 现象、观测方、指标、单位、测试对象和范围 | 客户感知与网络侧观测 |
| 故障责任方 | 明确责任认定及来源 | 经办人、处理部门、供应商 |
| 故障原因 | 已确认根因、候选原因、排查结论 | 告警机制、故障表现 |
| 处理过程 | 时间、主体、动作、对象、结果 | 流程流转和实际排障动作 |
| 故障地点 | 已定位故障点，附位置粒度 | 客户地址、业务端点、检查节点、告警位置 |

每个要素具有 value、status、evidence_refs、candidates 和 review 信息；缺失值为 null，不用“正常”“其他”等填充。status取 documented（原文记载但未核实）、confirmed（有明确确认依据或人工确认）、unknown、conflicted。模型自评置信度不得作为唯一发布门槛。

时间保留原字符串、来源时区和标准化值。仅在时区已知时转换UTC；来源无时区时按可配置的系统口径解析，并标记 assumed，不根据故障城市猜时区。持续故障不填结束时间，不生成最终故障历时。

## 7. 校验要求

| 规则 | 行为 |
| --- | --- |
| 恢复早于发生、负历时 | 标为关键冲突，保留原值，禁止静默修正 |
| 正文时间与字段时间不一致 | 分别保存候选，提示核对时间语义、时区和复制错误 |
| 无告警/有流量/排除返单 | 仅形成范围内排查结论，不能自动认定业务恢复 |
| 原因栏只含告警解释或正常检查结果 | 原文保留为排查或告警说明，根因保持未知 |
| 缺责任证据 | 责任方保持未知，不按供应商或处理部门补齐 |
| 不同电路号或新旧CID | 建立映射候选，未确认前不合并服务身份 |
| 旧单、作废单、重复告警 | 保留关联及状态，不作为当前事件的有效最终结论 |
| AI摘要与其原邮件重复 | 标记衍生来源，引用原始证据优先，避免双重计数 |
| 附件解析失败或低质量OCR | 标记材料不完整/待复核，指出影响的要素 |
| 新旧结论冲突 | 显示变更和证据；不能仅用最后一条记录覆盖既有确认结果 |

## 8. 报告内容

报告包括：工单标识、报告类型与版本、生成时间、数据截止时间、事件概述、七要素、关键处理时间线、恢复和验证情况、未决事项、内部证据索引及审核记录。

模板只消费经过校验的结构化数据。模型生成概述时只能使用该数据中的事实，每个事实应可回溯。报告保留“客户反馈”“供应商称”“检查显示”等归属，不把单方陈述改成最终事实。

## 9. 验收与评测

先建立50张分层样本用于规范及开发，另准备至少50张独立验收样本；真实分布允许时覆盖业务性能、业务中断、中继、设备、已结案、处理中、作废、缺失和冲突案例。附件样本覆盖截图、扫描PDF、原生PDF、DOCX、EML。相同事件、关联工单和重复邮件不得跨开发集与验收集。

由业务人员标注可确认答案、证据和允许未知的字段；关键分歧双人复核。以下是拟定试点目标，不代表现有能力，需要基线评测后由业务确认：

- 有证据的七要素提取准确率≥95%，各字段单独报告，不能用大量未知项抬高成绩。
- 可提取要素召回率≥90%；未知、冲突识别分别评测precision/recall。
- 证据定位正确率≥98%；导出结构合法率100%。
- 固定验收集中无证据的确定性根因、责任、恢复结论为0例；此项不等于对所有生产数据承诺零错误。
- 必测时间倒置、负历时和伪造证据引用用例全部拦截。
- 同类工单的人工整理时间中位数较基线减少≥50%，统计包含审核和修订时间。
- 初始性能预算：50条以内日志、正文2万字以内的纯文本任务P95≤60秒；20页以内附件任务P95≤180秒。实际模型和硬件确定后压测校准。

同时记录整单可用率、人工修改率、附件失败率、单任务模型成本和耗时；开发人员自评不能替代业务验收。

## 10. 安全、权限和可靠性

- 默认不外发工单数据；模型/OCR通过可配置适配层接入公司批准的内网或云服务。未确定出口策略时使用脱敏或合成数据开发。
- 来源内容均为数据，邮件、附件中的指令不得触发工具操作或改变系统规则；解析器禁止执行文档宏、脚本和外链加载。
- 上传做类型和大小检查，文件与正文不写入普通应用日志；HTML输出转义并清理可执行内容。
- 多用户试点必须落实工单级访问权限、下载权限与审计；本地演示版本仅绑定本机，不作为共享生产服务。
- 数据保留周期可配置，正式试点前由公司确定；删除覆盖源文件、解析结果和衍生报告，备份按组织策略执行。
- 任务异步执行、有限重试、幂等导入；单文件失败可见且可重试，禁止重复生成或静默丢材料。
- 人工确认与已审核报告不可被模型重跑覆盖；所有结果绑定输入快照、模型/提示词/规则/模板版本。

## 11. 待确认事项与默认推进方式

| 待确认项 | 未确认前的推进方式 | 影响 |
| --- | --- | --- |
| NOC读取接口、导出结构、附件入口 | 建立标准导入包和合成连接器 | 不阻塞核心开发，阻塞真实自动同步 |
| 模型及OCR服务、部署资源、数据出口 | 模型适配层和确定性测试桩 | 不阻塞框架，阻塞真实质量及性能验收 |
| 正式报告模板与结案必填口径 | 使用本PRD的阶段/结案草稿模板 | 影响业务验收 |
| 原始样本及标注人员 | 先用四类已观察问题设计脱敏测试案例 | 阻塞真实准确率评估 |
| 时区、责任和地点的组织口径 | 保留原文，未知不强行标准化 | 影响字段最终确认 |
| 身份认证、角色和保留策略 | 单机演示，权限层预留 | 阻塞多人生产试点 |

本PRD建立产品范围和验收基线；实际生产接入及上线安排需在上述依赖落实后确定。
