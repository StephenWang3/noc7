## 具体修复

1. **评估先校准。** 核对 E04 的原始邮件、源邮件日志与导出材料：邮件 ID、发送方、发送／收到／关联时间及导出正文相互对应，均在最早销障前；正文与导出器的头部包装逐字重建一致。该邮件属于独立上游原文，允许作为截止前输入。同文的结案转录继续隔离，AI 摘要不增加来源或证据数量。
2. **支持锚点补全后新建冻结集。** 给 E04 的地点和原因登记实际保留邮件／日志的支持；七例的参考事实值、要点、同义词、允许状态与人工审核状态均保持原样。没有将 E03 新增归因反向写成参考答案，旧 `dataset-r2` 和旧评分没有覆盖。
3. **两类有限的语言补漏。** 明确客户侧归因、责任归属陈述可作为 `claimed/documented`，不升级为正式认定；有明确故障原因上下文的英文 RFO `Location: Between … and …, …` 可作为故障段记载。疑似、否定、待核实、测量中、笼统连接段、业务端点、告警位置和测试 IP 继续区别处理。
4. **保存本地处理过程。** 新增可选的仓库外模型诊断目录，保存原始响应、结构补全、本地重算前后结果、类别变化／删除与拒绝状态。本轮七次真实请求全部留有记录；模型没有交候选与本地删除不再混为一谈。

本调查分支原先缺少 #12 已完成的结构补全及类别重算修订。本轮以 #12 最终分支版本 `7f947bb22ae0a42d6c0ced6115f81a7fdee75c3a` 同步 `text_ground.py`、`text_http.py` 及其对应测试，再实施上述补漏，没有恢复旧的模型标签信任行为。共享 schema、原始包、外发闸门和附件解析器没有改动。具体约束见 [决策记录](decisions/preclosure-email-and-fact-recall.md)。
