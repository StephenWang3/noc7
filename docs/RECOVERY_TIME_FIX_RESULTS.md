## 修复与目标五张复核

混合引用的默认时区改为检查候选原串是否被引用字段实际承载，不再要求引用列表全部是字段；无关字段仍不能授予默认时区。新增完整日期十二小时制解析，保留 PM、UTC、精度和原文，歧义斜杠日期不猜。规则及取舍见 [决策](decisions/recovery-time-normalization.md)。

四张混合引用单的字段候选均恢复为 `assumed`，但只有三张新增正式值：两张 `documented`，一张 `confirmed`。后一状态沿用模型关系中的客户正常确认依据，**不等于人工审核通过**。第四张原模型状态为 `unknown`、未选中，候选变为可采用后仍不替它选择。

对三条新增与结案材料作汇总核对：3/3 的精确原串由字段承载；其中 1/3 有正文恢复陈述在小时分钟上相同，但缺少独立的完整日期、秒数和时区。其余 2/3 的正文只有稍后正常／可结单或主链路修复的陈述，不能证明字段的精确恢复时刻。保护正常、主链路恢复和客户业务恢复也不能未经语义核对直接等同；更早的恢复表述留在私有复核中，不另用词表推断关系。

因此，新增三条都与字段原串及系统时区假设一致，但没有一条凭现有独立结案／RFO 依据完成“完整日期、秒数、时区和业务含义均获人工确认”的验收。材料中没有独立依据时明确记为无法确认，不把系统保存报告视为人工审核。

格式受限单的 AM/PM 恢复原串现在正确归一为显式 UTC，但与另一条业务恢复字段候选不相容，最终由 `unknown` 变为 `conflicted`，仍无正式恢复值。进一步核对原始回答：模型原答曾选中该正文候选，未选中的是替代字段候选；不能把先前“伴模型未选中”概括为整栏从未选择。其 RFO 的起止与影响时长也不能直接互相印证，不按 RFO 标题决定真值。

## 影响范围与可重复性

输入取自 #22 使用的原映射，绑定到 `~/.noc7/time-cause-validation-trial/` 的唯一响应，与 `~/.noc7/time-cause-review-fixes-final/` 的完整结果比较。实施前冻结 31 份绑定及旧分析文件哈希，校验原包全部材料，旧留档没有被改写。

新输出为 `~/.noc7/recovery-time-fixes-replay/`；冻结记录为 `~/.noc7/recovery-time-fixes-freeze/`。逐单原文、身份、结果、复核及来源仅在这些私有目录，不进入 git。主要复核入口：`five-ticket-review.json`、各单 `comparison.json`、`summary.json`、`unchanged-check.json`。

30 份成功结果的模型原始三栏完全未变；变化只落在目标 5 张的时间栏，包含其中 1 张的起障。其他状态 9 张及其他要素、事件、处理过程、建议、身份和完整证据均未变化。原有 8 张恢复竞争单没有变化；原有实质引文不匹配拒绝单仍拒绝，没有放宽来源检查。

禁网重放由脚本将 socket 创建替换为拒绝函数，不使用模型密钥或发起新模型请求；每单重建完整报告并保存回放，再读回校验。30 份成功回放内容相等，Word 包结构均可读。独立数值核验为 82 条匹配、6 条未评估、0 条不匹配；这只是时间表示检查，不是语义准确率。

复现时将 `BASELINE` 设为 #22 原输入映射所在目录，输出必须改为新的私有目录：

```sh
uv run python scripts/check_time_cause.py replay \
  --baseline "$BASELINE" \
  --responses ~/.noc7/time-cause-validation-trial \
  --expectations ~/.noc7/time-cause-review-fixes-final/frozen-expectations.json \
  --compare-results ~/.noc7/time-cause-review-fixes-final \
  --out ~/.noc7/recovery-time-fixes-next
```
