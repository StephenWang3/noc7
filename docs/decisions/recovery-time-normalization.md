# 恢复时间归一：字段承载与十二小时制

状态：已采纳。用户确认混合引用分别归一、沿用既有冲突校验；本次只修本地时间处理，不替模型选候选。

## 问题与证据

输入为 #22 分支的已结单专项报告及仓库外的冻结明细，实施前核验全部三十一份原包、唯一模型响应、请求证据摘要及旧结果绑定。四张恢复候选的原串确实存在于引用字段，却因 `_normalized_time` 要求全部引用均为字段而失去默认时区。另一张含完整年份、AM/PM、UTC 的斜杠日期未归一，其日期顺序可唯一判定。

既有规则见 [时间与原因校验决策](time-cause-validation.md)：字段可按系统口径假设，正文不得套默认时区，不能按记录发送时间补正文日期。

## 决策与取舍

默认时区资格依赖承载时间原串的证据，而非引用列表的组成：候选直接引用的字段必须经 `match_quote` 证实包含原串，允许空白等价。引用了无关字段不能获得默认时区；额外引用正文不取消已证明的字段资格。字段没有默认口径时仍不能获得假设偏移。原串、证据、模型关系和原始回答不改写。

字段时间按 manifest 口径标为 `assumed`，复用公司报告中的假设披露；正文仍只使用自身明确时区或经引用的锚点。正文别处出现另一时区不自动覆盖字段。候选明确引用的日期／时区锚点与当前归一结果不一致时阻止采用。其他时间差异沿用模型提供的候选、事件、范围、用途及既有区间冲突检查，不新增程序语义词表或来源排序。

代价是：模型没建立的业务关系仍不能由程序证明，正文不同时间也不自动成为新候选。相比把所有混合引用差异一律拦截，本方案避免将确认动作、其他事件的时间误判为本次恢复冲突。

`parse_time` 支持完整数字日期的十二小时制，处理大小写、分钟／秒、午间与午夜及显式时区。年后置斜杠日期仅在日月可唯一判定时解析，歧义不猜；日月年点分格式保持既有约定。正文提取整体匹配十二小时制短语，避免丢 PM、截取局部时钟或借相邻时区。非法十二小时制和日期保留原文但不产生 ISO。

## 验证及兼容边界

不修改共享 schema、提示词、旧响应或旧结果；新代码通过保存的原响应重新解码，执行完整证据校验、报告生成及回放验证。对照脚本独立使用标准库核验数值表示，比较前检查集合唯一性、包／证据／响应绑定及旧结果身份；逐单差异只保存到新的私有目录。

新增合成测试覆盖混合引用、无关字段、空白等价、正文时区、锚点矛盾、模型未选、候选冲突、十二小时制及非法／歧义格式；原有语义与来源检查继续生效。默认规则链路的合成 gold 差异与修改前完全一致，历史 gold 不改写。

结果见 [修复核验报告](../RECOVERY_TIME_FIX_RESULTS.md)。填出变化只说明保存回答在新本地处理下的效果，不能解释为准确率提高。原有八张恢复来源冲突的业务裁决、客户责任口径及模型重试均不在本次范围内。
