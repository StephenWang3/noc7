# 完整工单的实际交付试跑口径

状态：已采纳（2026-10-29）。依据：用户同意将完整工单（含结案材料）交给 DeepSeek，生成审核报告、公司 Word，并统计填出率和原文可追溯率。

## 输入与选择

直接使用 `~/.noc7/real/` 与 `~/.noc7/sample-expansion-it6b5svf/captures/` 的顶层完整包，不使用 `dataset/inputs` 的截止前切分包。前者十五包，后者十七包；按工单身份去重后共三十一张，一张跨批重复。不再到 NOC 采集；不触发工单、邮件或报告状态变更。

本轮的“完整”指已导出包不再按首次结案动作截断，并非声称 NOC 所有历史附件均已覆盖。清单、文件哈希先校验；解析器的失败、未支持、低质量、衍生摘要和签名过滤继续生效。其中二十一张详情已结单，其余十张按阶段草稿单列，不能声称三十一张均有结案材料。截图只通过本地解析器产生可用文字，原图不发 DeepSeek。实际请求证据与完整包清单均留存，材料未覆盖情况另列。

## 指标及分母

1. 运行交付率：生成完整审核 Markdown／HTML、公司 HTML／Word 和分析 JSON 的工单数／全部去重工单。失败与拒绝留在分母，不为提高通过率重新生成答案。
2. 正式填出率：最终 `SevenElements` 每栏非空值的工单数／全部三十一张。处理过程有步骤即非空；候选存在、未知与冲突不当作正式填出。另列有候选工单数。
3. 建议覆盖：责任方和地点的原始候选工单数、原始非空值工单数分别列出。二者不能相加，也不计入公司报告正式填出；所有建议仍待确认。已绑定实际请求的被拒答复，其原始建议仍统计，无法解析则另列。
4. 候选原文可定位率：每栏全部最终保留候选为分母（处理过程以步骤为条目），全部引用编号存在且至少一个被引片段可匹配候选摘录为通过。严格子串、仅 Unicode 空白等价、记录时间元数据分别计数；缺来源、不匹配也在分母。时间比较 `time.raw`，不把归一后的 ISO 字符串当作原文。记录时间元数据不混入正文子串匹配率。每条匹配保存原文范围及来源编号，证据定位器可继续定位字段、日志、邮件或附件。
5. 填值的候选可定位：有 `selected` 时查被选候选；现象和步骤查其候选／步骤。此数衡量候选引文的可定位性，不证明拼接文字或时间归一、业务语义正确。建议原始值的覆盖与候选引文统计分开，不以候选匹配替代原始值验证。

填出率分母包含所有失败工单；候选可定位率只描述实际交付的候选集合，必须同时展示运行失败数。建议另给全体模型原响应的候选统计，避免只看成功答复。零分母写“不可计算”，不能写零准确率或百分之百。

## 与旧评估的关系

旧切分评估用于考察结案前材料支持的参考一致程度，本轮用于考察结案后能交出什么报告。完整输入已含人工结论，不再拿同一结论宣称独立准确率，也不覆盖历史成绩。结案一致性只能作为含参考输入的复述一致性；本轮不新增或修改人工标注，不提供独立准确率。

对已有八张定向扩样工单中的七张可匹配工单，按源身份配对，与当前建议机制下的历史原响应离线重放比较填出数和建议覆盖。它是描述性对照：输入改变且模型调用不同，不将差值解释为单一功能的因果收益。旧六／七例等不同样本历史分数仅作背景，不与三十一张总分母混合。

## 实现与复核

`scripts/run_full_ticket_trial.py` 调用现有 `analyze_with_context`、模型配置与外发闸门、报告和回放写入器，不改提示词、抽取规则、建议隔离或七要素契约。最多四个并发工作线程，本次使用三个；网络层沿用配置的有限传输重试，校验拒绝不重新请求。每单独立原响应审计目录，保存重算前后快照。

单张输入、异常、原响应、报告、映射、指标及离线核验均只放仓库外 `~/.noc7/`，目录权限 0700、文件权限 0600。仓库只提交统计脚本、合成测试、白名单计数及方法说明。审核仍在 NOC 工作台进行，不增加审核界面或自动采纳操作。

结果见 [完整工单试跑统计](../FULL_TICKET_TRIAL.md)。
