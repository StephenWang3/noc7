# 时间与原因：模型关系和独立约束校验

状态：已采纳。用户选择单次模型＋结构化关系；起障允许带标签的告警替代时间；自动原因状态最高为 `documented`。

## 问题与取舍

输入调查来自 #18 分支的 `docs/TIME_CAUSE_STAGE_TRACE.md`，不是假定报告已并入。已复核本机追踪、三十一份审计身份及七百一十八份源文件哈希：成功集合二十项在 grounding 清空，另一项原因在结构补全因概述与候选标题不同而丢失。原始二十一项中十三项有明确规则／结构限制，一项语义越界，一项规则漏识别伴等级过高，六项涉及含义、冲突或推测范围；不能全部恢复。时间候选没有删除，原因候选从七十六条删至四十四条。

比较过三种实现：单次模型提交关系、第二次模型做语义复核、单次关系加旧词表提示。采用第一种，避免把词表变成新的隐性裁决；代价是程序无法独立证明模型理解正确。第二次模型也不是独立人工真值；本次不增加该调用。`RulesProvider` 继续作为既有对照，时间／原因的词表不参与新模型链路，其他要素不扩大范围。

## 关系与本地记录

`TimeCandidate.relation` / `CauseCandidate.relation` 可缺省以读取历史数据。新提示词要求关系包含事件分组、范围、是否本次事件、断言确定性及上下文原文。事件分组和范围本身是模型判断，程序只检查完整性与分组内一致性，不宣称验证了真实事件身份。

时间分类追加业务起点、业务恢复、确认动作和协议 Up／Down；现有类别含义不变。日期、时区和客户确认依据都必须单独引用。原因声明故障／机制／作业／现象／排查／恢复、是否发生、是否影响业务及陈述方；明确设备故障和推测机制分候选。否定与推测不能随一大段文字被升级。`contradicts` 只引用同要素候选，表达模型识别的语义矛盾；程序不能靠相同事件内有不同原因就臆断冲突。

解码器在结构补全前保存三栏 JSON 到本地 `SemanticAssessment.original`，之后生成 `checks`。模型提交这些本地字段或人工审核记录会被拒绝。检查记录不等于人工复核；`review` 仍不能由模型创建。未知类别按 `unclassified` 留候选，格式不完整的原对象保存在原始三栏。重复／无效选中编号不猜选。选中项有效时正式值取候选原文，不要求模型概述与标题逐字相同。

来源不存在或实质引文不匹配仍整单拒绝，包括结构补全未能使用的原始关系引文。其余关系不完整、不符合正式用途、缺精度或推测未明，只阻止对应结论，不删候选。引用匹配沿用 `match_quote`，只折叠空白，保留相对于证据的半开字符范围。解码使用实际请求证据，最后在完整证据重新校验并刷新范围，不能比较两种证据文本的字符范围是否相等。

## 正式输出与冲突

起障允许明确业务起点、客户报告起点及有标签的告警替代时刻。恢复只接受模型明确关联本次业务的实际恢复时刻；客户稍后确认“已经正常”的动作不能替代此前恢复时刻。协议状态、修复完成、流程时间和仅有日精度的时间留候选。`fault_end_time` 和 RFO 标题没有自动放行资格。

同事件、范围、用途的时间按精度解释为半开区间；分钟精度覆盖一分钟，秒精度覆盖一秒。不重叠才构成数值冲突；不同用途或范围不互相否定。同一瞬间不同偏移不冲突。同组冲突保留双方且正式栏为 `conflicted`；不同组的冲突不能清空已选中且无冲突的时间。明确业务恢复早于业务起点时，恢复留待核实，不生成历时。原因的显式矛盾同样保留双方，不按来源排序替用户决定。

正式时间须有日期、至少分钟精度和可用时区。完整原文先交 `parse_time`，再处理时间短语，覆盖紧贴秒数的偏移、全角冒号、英文日期及 RFO 的日.月.四位年格式。显式时区优先；日期／时区锚点不一致时保留原文待核实，不静默改偏移。无正文日期不能用邮件发送／处理记录日期补齐。只有系统字段按 manifest 默认时区归一并标 `assumed`；无明确时区的正文不借系统默认口径，也不按地点猜时区。日月顺序不明的斜杠短日期不猜。

自动原因最高为 `documented`，公司报告注明陈述方及“有记录，未经人工审核”；`root_cause_confirmed` 候选类别不代表已经人工审核。推测机制、现象、自恢、排查和否定只能保留候选；已发生且明确影响本次业务的作业可按记录采用。责任方和地点仍只展示 AI 建议，不从原因补定责。

公司 HTML 与 Word 共用 `build_company_report`：时间显示口径，冲突和材料不足显示待核实。告警替代起点不计算业务故障历时；范围或事件分组不一致也不相减。有完整业务起止但无客户确认时只显示带限定的暂估历时；有独立于引用／摘要的客户确认依据才输出最终历时。程序检查确认引文来源与结构，语义仍依赖模型。

## 兼容和验证口径

新增字段默认空，旧结果及 `ReplayRecord` 可读取，旧回放不自动重解释；旧原响应重新解码时，缺新关系只保留候选，不借旧词表补关系。已经保存的错误时间归一值不能因兼容而绕过当前引用与归一校验。

合成正反例预期在实现前冻结到 `tests/llm/cases/time_cause_expectations.json`，私有调查判断和哈希同时冻结。覆盖自恢误作根因、故障与推测并存、确认动作、告警口径、协议状态、字段与 RFO 冲突、偏移、全角时间、日期、标题差异、空白等价、重复来源和缺关键锚点。新增测试另覆盖日.月.年 RFO 格式、来源篡改、无效关系、日期／时区锚点和编号歧义。

`check_time_cause.py` 在发送前验证原包及唯一审计响应，绑定包哈希、实际请求证据摘要和完整请求对象。离线模式禁用 socket；在线模式每包最多一次请求，关闭自动重试，保持开发期 DeepSeek 官方文本外发闸门。需要新关系才能测新提示词，因此旧响应不冒充新能力。新响应保存后可完全离线重新解码、完整证据校验、生成报告和回放，无需再请求。

```sh
uv run python scripts/check_time_cause.py replay \
  --baseline <原完整试跑修订目录> --expectations <私有冻结目标文件> \
  --out ~/.noc7/time-cause-validation-replay
uv run python scripts/check_time_cause.py trial \
  --baseline <原完整试跑修订目录> --expectations <私有冻结目标文件> \
  --out ~/.noc7/time-cause-validation-trial
uv run python scripts/check_time_cause.py replay \
  --baseline <原完整试跑修订目录> --responses ~/.noc7/time-cause-validation-trial \
  --expectations <私有冻结目标文件> --out ~/.noc7/time-cause-validation-trial-final
```

每次输出必须为新的 `~/.noc7/` 私有目录，不能直接重用上述已存在的历史目录。脚本的目标状态对照只列待语义复核项，不自动当作语义准确率；实际语义相符与推测范围仍须逐项对照冻结判断。填出率、引文有据率、归一正确及正式状态分开报告。旧评分和 gold 不修改，Qwen 只做同协议模拟验证，不声称内网实调。真实输入、响应、逐单报告及冻结原文不进 git。
