# 已结案工单的人工参考评估

已交付独立的 `python -m noc7.evaluation` 命令，完成参考转录核验、截止前输入隔离、规则基线、结果导入评分和重复评分。真实原件、标注、映射、证据与长篇明细全部留在仓库外。本文件只保留计数和语义类别。

## 本轮取样与来源

从已有十五包中核对五张已结单工单，另外只读导出十五张（A05 对应单及十四张新候选），共检查二十张。新候选来自最近三个月的第一页五十条已结单记录，按标题粗分类轮流选取；这是有限便利样本，不是随机抽样，也没有遍历工单池。

对这二十张逐一调用已有报告记录的只读接口，全部返回空列表。本轮浏览器采集器累计请求 368 次，串行限速，请求预算未耗尽；未调用生成、保存、报告下载或查看邮件的写回方法。

用户提供的 A05 DOCX 与 NOC 的完整工单号、客户及去空格后的电路号一致，原先的电路号差异只是空格。该单不属于原十五包，已补采。报告具名，但审核人空白，因此作为未审核的正式报告参考，不标成已审核答案。

二十张的筛选结果：

| 阶段 | 数量 | 说明 |
| --- | ---: | --- |
| 检查的已结单候选 | 20 | 只读采集与本机原包核对 |
| 缺少可确认的明确结案节点时间 | 4 | 不用列表状态或最后一条日志猜截止点 |
| 缺乏可直接冻结的实质结论要点 | 9 | 多为简略流程／检查意见，仍需语义标注；不代表没有任何人工材料 |
| 形成候选参考标注 | 7 | 一份正式报告、六份具名人工最终处理意见 |
| 引文要点核验未通过 | 0 | 原先把恢复描述里的「无」当成否定、整例排除；收紧后要点能在引文中核对 |
| 最终进入评估 | 7 | 正式报告一例、人工结案意见六例；基线运行全部成功 |

七例源系统分类为“不通”五例、“丢包”两例，未覆盖设备、中继等布局。参考涉及模块故障、供应商断纤 RFO、计划升级割接、资源拆机核查和本方设备观测等语义。资源状态、局部无告警不标成确诊根因；供应商声称不升级为现场确诊。本轮没有独立采用邮件最终结论作为参考来源，供应商 RFO 的人工结案转述归入人工结案意见。

## 输入隔离

原工单包没有改写。以最早的结案动作（含销障）为截止，重新生成独立输入包：不带真实编号、标题、最终状态、分类、关联单或未核对历史的最终字段。参考报告、结论锚点、副本、源响应留档、AI 摘要及无法核实归属／完整检查的附件均隔离。

七例隔离记录分别计数，字段、日志、材料属于不同层级，不相加当作附件数：

| 排除原因 | 记录数 |
| --- | ---: |
| 参考来源／报告／结论副本 | 27 |
| 截止后日志 | 20 |
| 没有历史依据的最终字段 | 343 |
| 原始响应留档材料 | 14 |
| 邮件、详情或附件归属不足 | 81 |
| AI／其他衍生材料 | 8 |
| 无法完整检查的材料 | 7 |

原先六例里，截止提前到销障，有两例合计多排除 3 条销障当条及签收前日志；其余排除原因在这六例中没有变化，已有事实的输入锚点数量也没变。新纳入的一例带来上表相对旧计数的其余增量。

参考要点和同义词在读取系统输出前冻结，输入支持由原文锚点重新验证。时间事实的可支持性使用独立原文时间解析与冻结的语义标注，不调用被测提取器决定分母。保守隔离会丢失部分原本有用的事实，因此单列“未确认输入支持”，不把缺少这些材料算成提取器遗漏。

自动副本检查覆盖显式报告标记及长引文词法副本；它不能证明任意改写均无泄漏。此次仍逐项核对了纳入的来源及隔离依据，不能把此样本结果推广为通用防泄漏保证。

## 基线结果

评分单位是“某样本中某来源的一条事实”，不是工单正确张数。同一事实的不同来源分开统计，不能当成独立故障。

| 要素 | 一致 | 遗漏 | 明确冲突 | 待判定 | 未确认输入支持 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 结束时间 | 0 | 1 | 0 | 0 | 0 |
| 故障现象 | 1 | 0 | 0 | 0 | 3 |
| 故障原因 | 0 | 1 | 0 | 1 | 1 |
| 处理过程 | 2 | 0 | 0 | 0 | 0 |
| 故障地点 | 0 | 0 | 0 | 0 | 1 |
| 合计 | 3 | 2 | 0 | 1 | 5 |

发生时间、责任方没有冻结的参考事实，不能据此计算效果。已纳入参考中没有标记来源冲突。

在有输入支持的六条事实中，五条可判定：三条一致，两条遗漏，一条待判定。因此总体参考一致率为 **3/5（60%）**，可判定覆盖率为 **5/6（83.3%）**；另五条未确认输入支持不进入分母。新纳入的一条现象没有截止前依据，所以只增加未确认输入支持，不改变一致率。这些都是小样本参考一致性指标，不是业务正确率、整单准确率，也不是对人工结论的正确性认证。

| 来源 | 一致／可判定 | 待判定 | 可判定／有输入支持 | 未确认输入支持 |
| --- | ---: | ---: | ---: | ---: |
| 正式报告 | 1/3 | 0 | 3/3 | 1 |
| 人工结案意见 | 2/2 | 1 | 2/3 | 4 |
| 邮件最终结论 | 无分母 | 0 | 无分母 | 0 |

两项遗漏均来自正式报告对应案例的原因和恢复时间：隔离后的原文有依据，现有规则仍只保留候选，未形成结论。另一个原因事实已有系统结论，但冻结要点未全部命中，保留待判定；没有查看输出后追加同义词。两条处理过程事实覆盖了冻结动作要点和顺序，但这不证明所有处理步骤均无遗漏。

结案意见的 2/2 只包含两条可判定事实，另有待判定及输入支持缺口，不能理解为该来源质量已达百分之百。地点和责任方仍缺少可评分覆盖，不能据此宣称模型已解决这些要素。

## 本机产物与复现

入口和标注约定见 [导出及评估说明](../scripts/noc_export/README.md)，决策见 [人工参考评估 ADR](decisions/human-reference-evaluation.md)。

本轮输出根目录为 `~/.noc7/real-eval/`：

- `captures/`：只读导出的原始工单包、候选与独立已有报告记录。
- `selection.json`、`sampling.json`、`reference-originals/`：冻结前标注、筛选原因及人工结论转录；正式 DOCX 原件仍在原本机样例目录。
- `dataset-r2/inputs/`：提取器只读取的七份隔离包；并列的 `references.json` 含来源、原文锚点、输入支持、逐项排除记录和原包映射。
- `baseline-r2/`：七份 `analysis.json`；`scored-r2/report.md` 和 `scored-r2/details.json` 为本机长篇明细，`scored-r2/summary.json` 为白名单计数。
- `replayed-r2/`：同一输入、参考和结果的第二次评分，与 `scored-r2/summary.json` 一致。
- `dataset/`、`baseline/`、`scored/`：修订前的六例结果，截止点落在更晚的结单签收，不要当作本轮数字。
- `preflight/`：冻结前仅核验来源与输入的预检，不包含提取结果，不作为最终评分输入。

真实文件没有提交到项目文件页。在采集机器上查看：

```sh
open ~/.noc7/real-eval/scored-r2/report.md
```

复跑须使用新的输出目录；不能覆盖已冻结参考或现有报告。其他提取器使用 `dataset-r2/inputs/` 中相同工单包，沿用默认解析证据，输出至 `<结果目录>/E01/analysis.json` 等路径，再调用 `score`。清单或解析证据快照不一致会拒绝评分，原先对完整结案包生成的报告不能代入。

验证完成：`uv run pytest -q` **306 passed**；浏览器离线白名单检查通过；`noc7 schema check` 和 `noc7 gold check` 通过；真实七例基线与两次评分成功，两次 `summary.json` 一致；私有产物目录／文件权限检查通过。原有合成 gold 默认链路的已知语义差异不在本轮修复，测试全绿不表示这些差异已消失。
