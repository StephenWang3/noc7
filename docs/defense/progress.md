### 遇到的问题和解决办法

1. **A1、A2 并行开发怎么不打架。** 按材料类型分工，证据编号带材料前缀（`M03/msg:1`），两条线只交换证据片段；默认注册表按包名自动加载，未交付的一方由“不支持”兜底。外发闸门和运行依赖都提前放进 A0。详见决策 0003。
2. **标准答案不能和解析器的实现绑定。** 写标准答案时还不知道解析器会怎么切片段，所以证据用“锚点”（材料 + 字段/处理过程序号/邮件消息/页码）表示，文本按要点判分。`noc7 gold check` 会核对每个锚点真实存在。
3. **“原因栏”“责任栏”不能直接照抄。** 起初只想用一个 `cause` 字符串，写 S02、S05、S09 时发现原因栏分别是计划割接、可能原因清单、排查结论。改为“候选 + 类别”，只有确认或某方陈述的根因、计划作业能成为结论，规则写进校验器，模型输出不合规会直接被拒绝。
4. **时间的时区。** 源系统字段没写时区，但口径是 GMT+8；上游邮件用 UTC；海外设备日志完全没写时区。做法：工单包声明 `default_timezone`，按它解析的时间标 `assumed`；原文写明的标 `explicit`；不根据城市猜时区。`TIME_TZ_MISSING` 只在时间明显是另一种口径时报，否则每张单都会报十几条，审核人员会忽略。
5. **合成数据不能像真的。** 编号统一 `SYN-`；IP 只用文档保留网段，域名只用 example 域；这些检查写成测试，以后新增样本也会被检查。
6. **附件标志不可靠。** S10 的处理过程顶层“有附件”为 false，实际有一张截图。工单包按条登记实际附件，标志只留档，不一致时导入层给提醒。

### 失败的尝试和修正

- 时间解析最初的正则不认识“14时38分”这种只有时分、没有秒的中文写法，测试发现后修正；
- 合成数据检查一开始把 `attacker.example`（保留顶级域）和邮件地址里的 IP 误判为真实数据，调整了规则；
- 标准答案的“候选类别”起初是单个值，但同一个候选常常可以合理地归到两种类别（例如客户报告时间也可以看作邮件时间），只认一种会误判，所以在写标准答案前改成可接受类别列表 `kind_in`，并校验每个类别都是已定义的枚举值；
- P04 的处理过程最初没有按时间排序，发现后按记录时间重新编号。

### 需要用户或业务方确认的事

- 标准答案由编写合成样本的 agent 标注，**责任和原因的判断口径需要懂业务的人复核**；
- `docs/IMPLEMENTATION_PLAN.md` 是早期输入文档，里面的工作日估算没有改（本次只按要求修改了 `ARCHITECTURE_OPTIONS.md`）。

### 问题、修正与取舍

1. **真实可运行但不依赖外部模型。** `rules` 做保守基线，`replay` 保存抽取结果并绑定输入/证据两份哈希；模型服务不是演示和测试的前置条件。设计论证见决策 [0005](../decisions/0005-text-extraction-validation-and-replay.md)。
2. **恢复确认不能只看单个词。** “同意结单”不提升恢复状态；“客户尚未确认恢复”不能命中正向确认。客户确认恢复但根因尚未查明时，恢复仍可成立，原因继续未知。
3. **跨日日期不能直接照邮件头。** UTC 邮件头的日期可能比 GMT+8 正文小一天。补齐裸时刻时先按正文明确时区换算日期；海外设备日志没有时区就保留 unknown，不按城市猜测。
4. **输出转义要测试实际模板名。** `.html.j2` 没有被按 `.html` 后缀判断的自动转义覆盖，恶意标签测试发现后改为按导出格式显式开启。Markdown 同时转义 HTML、链接及图片语法。
5. **A2 不需要修改 A1 入口。** A2 只产 `EvidenceSpan`，默认注册表自动发现；A1 已用合成结构化曲线片段测试分类别统计和首次非零候选，不声称已实现图像识别。低质量、失败、不支持各自有状态和提示。
6. **质量阈值与语言覆盖的代价。** 暂用 0.7 作为保守复核阈值（工程判断），不是已校准概率；复杂表达可能漏抽，现有问题提示也可能偏多。真实标注集到位后需要校准规则、阈值和模型。
