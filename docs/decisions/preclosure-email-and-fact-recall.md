# 截止前独立邮件、归因与英文定位的补充规则

状态：用户已选择“校准评估并补漏识别”，2026-10-28 实施。延续 [人工参考评估](human-reference-evaluation.md) 与 [文本模型契约](llm-text-providers.md)，不改变共享 schema、外发闸门或原始包格式。

## 问题与决定

调查发现，参考转录可以与结案前独立收到的上游邮件同文。旧逻辑有时按整段指纹排除转录，却因 HTML、项目符号和前缀差异留下邮件，且冻结支持锚点没有覆盖它。单纯补同义词或放宽结论不能解决这个评估问题。

新选择文件增加可选 `independent_emails`，每项包含 `log_seq`、邮件 `material_id`、逐字 `quote` 和来源审查说明 `provenance`。这是预先核对材料的声明，不是责任认定、人工业务审核或自动真实性认证。真实评估先核对源响应的邮件 ID、发送方、收取／关联时间及导出正文，再创建新的选择文件。

`prepare` 对声明继续做结构核验：

1. 日志是有明确截止前时间的邮件记录，且不是参考锚点或摘要。
2. 材料是可完整解析的原始 HTML 邮件，未标为衍生、排除或参考原件；日志挂接与材料 `origin.log_seq` 一致。
3. 只有该条原始邮件日志可以拥有这份材料；AI 摘要对同邮件的引用不增加独立来源，摘要继续隔离。另有普通日志挂接时拒绝放行。
4. 审定引文同时出现在可靠的当前邮件正文和对应日志；引用历史、签名或未完整解析内容不能作为依据。最终报告标记仍拦截。

经核验的独立邮件及其原始日志可以与最终人工转录包含相同事实。它们表示同一事件，不当作两条独立佐证。未审定的参考同文仍隔离；副本检查同时规范化 HTML，并检查多行实质引文，避免格式差异形成隐式例外。

新集冻结前补齐邮件与日志的输入支持锚点，保持事实值、要点、同义词和审核状态不变。旧集及其分数保留，不把新口径分数与旧口径直接比较。没有责任方人工参考时，只报告其有依据记载数量，不计算该栏准确率。

## 有限补充语义覆盖

- 明确的客户侧归因、责任归属陈述可成为 `claimed/documented`；疑似、否定、待核实不据此定责，经办方和供应商角色也不升级。普通归因不成为 `formal_determination`。
- 英文 RFO 的故障原因上下文，加 `Location: Between <命名位置甲> and <命名位置乙>, <地区>`，可成为 `located_fault_point/documented`。单独地点标签、测量中／待定位、笼统客户端连接段、IP 测试点、告警位置和端点字段不据此升级。
- 规则基线与模型重算使用同一组原文短语。模型只给候选时，本地也可从有依据候选选出唯一记载；互斥候选保持冲突。模型没有给出的候选不会由本地补造。
- `fault_area`、运营商下拉编码和合作方姓名没有改名为责任字段；最终快照字段没有历史证明时仍不进入截止前评估。

这是针对已证实写法的有限覆盖，不是任意自然语言的定位／定责能力，也不承诺填满这两栏。保留原文归属和证据强度，后续需要独立新增样本验证泛化。

## 可追溯记录

`noc7 analyze --provider llm` 新增可选 `--model-audit-dir`，必须指定仓库外的新目录。默认不保存原始响应。启用后每个请求有独立 JSON，包含输入／证据哈希、提示词版本、实际请求证据、原始响应、结构补全结果、本地重算前后快照、类别变化／删除摘要和接受／拒绝状态；不写请求头或凭据。

目录为 `0700`，文件为 `0600`；失败与被拒答案也保留诊断，但不会变成合格报告。响应收到后的诊断写入或校验失败不触发再次付费请求。诊断文件可能含真实原文，始终不提交仓库。

历史未保存的原始模型响应无法恢复。本次新记录能分清新一轮模型没交候选与本地删除，不能据此重写历史模型行为。
