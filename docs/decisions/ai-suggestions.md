# 责任方和地点保留为 AI 建议

状态：已采纳。依据：用户选择阶段调查的方案 C，并确认只覆盖责任方和地点、只在审核报告展示；候选有据率衡量引用可核验。

## 问题与取舍

阶段调查见 [分阶段调查](../RESPONSIBILITY_LOCATION_STAGE_TRACE.md)。模型已给出的地点候选被 `_ground_location` 的窄格式规则全部删除；另有事件和步骤将不换行空格写成普通空格，引发整单拒绝。这是业务判断重算和引用表示两种独立问题。

此前比较的三个方案为：扩展规则，改动较小但继续依赖句式覆盖；独立验证业务关系，能减少模板依赖但需要新的关系标注和冲突处理；直接展示待确认建议，能保留线索但增加人工核对负担。用户选择第三种，本轮没有采纳、修改、驳回界面。

## 契约与正式结论边界

`BusinessSuggestion` 与 `SevenElements` 分开。`original` 保存结构补全之前的两栏 JSON，包括原始状态、值、选中项、候选编号、原断言、归因、责任依据、地点角色和粒度；不把未知枚举替换为本地业务判断。候选只有值但没有候选依据的异常也保留并提示。`checks` 是本地核验记录，不能由模型提交。

OpenAI 兼容模型解码先分离建议，正式责任方和地点置为 `unknown`，不再调用两栏语义重算。其他五要素沿用原逻辑。规则提供方不受此变化影响，旧结果和回放缺少新增字段时按空集合读取；历史结果不会被自动重解释。

建议引用的来源必须存在，候选和非空值必须有来源。原始模型 `confirmed`、供应商主张和人工认定是不同概念；没有审核操作，不能把建议升级到正式结论，也不能从“客户侧设备故障”自动补出客户责任。公司 Word 和公司 HTML 的原因分析仍只读取正式七要素，不增加建议区。审核 Markdown 和 HTML 默认可见建议区，继续转义所有模型文字。

顶层 `quotes` 没有要素归属。仅当来源被建议独占时，将其移入对应建议；若同一来源还用于其他要素、事件或服务身份，则保留在正式引用校验中，实质错误仍拒绝。不能仅凭共享来源将正式引用降为待核对。

## 引用核验

共享匹配器先做严格子串检查，再把每段连续 Unicode 空白折叠成一个普通空格比较；不删除空白、不忽略大小写、标点、数字或单位。空白等价匹配保存模型原引文、源证据编号、原文片段和半开字符范围 `[start, end)`。范围相对于该 `EvidenceSpan.text`，证据自身的定位器继续追溯材料位置。

建议引文实质不匹配仍展示，标“待核对”；来源不存在仍拒绝。正式链路的候选、事件、步骤、时间原文和显式引文采用同一空白口径，其余业务及时间归一约束保持不变。空白等价记录进入结果并在审核报告展示；导出时重新核对建议记录及已有引用记录与源文本的一致性。

## 离线评估

`python -m noc7.evaluation replay-audit --dataset <冻结集> --audit-dir <原审计目录> --out <新目录>` 只读取已保存原响应。每个输入只能匹配一份响应，同时核对包哈希、实际请求证据哈希和完整请求证据对象；缺失、重复或不一致不会猜选响应。解码和报告走当前完整流水线，没有模型请求。

候选有据率＝（严格匹配候选数＋仅空白等价候选数）／两栏全部原始候选数。每条候选的全部来源必须存在，且至少一个所引来源匹配其原断言；不匹配、缺来源计失败。整单因其他检查拒绝时，已绑定输入的原始候选仍计入分母；原响应无法解析或无法绑定时另列不可统计单。值没有候选时不伪造候选，零候选单和零候选要素单列；分母为零返回空值。

重复候选按原始条目计入，不能据此声称独立佐证增多。统计另按责任方、地点拆分，正式结论仍由原 `compare()` 独立评分。核验率不证明责任归属、地点关系、距离或粒度正确，也不等于参考一致率；本轮不改变冻结要点、参考资格或历史成绩。

真实响应、报告、逐例核验和新评分仅保存在 `~/.noc7/` 的新目录，仓库只保留代码、合成测试与脱敏计数。
